# Porting this game

The game's own C lives in `progress/` (the decomp). This folder holds what only a port needs. Nothing here is game
data: no ROM bytes, nothing extracted from the ROM. Each build reads the ROM you own.

## The WebAssembly build (`port/wasm/`)

The matched C is compiled to WebAssembly, translated back to C, and built with a host for the PC. The game runs in a
memory laid out as the N64's, so the C needs no 64-bit fixes. Build and run it with decompdecomp's tool:

```bash
python -m decompnet.port.wasm /path/to/this/repository
port/wasm/build/game /path/to/your/rom.z64 [seconds]
```

- `exclude.txt`: matched C the build leaves out. That's libultra and the C library, which the host provides.
- `src/`: C only the port has. These are four functions the split had left as data, written from the assembly to
  behave like the game. They don't match yet; the project still has them open for agents.
- `overrides/`: the port's version of six matched files. Each file says why on its first line. They should move
  into the matched C behind `#ifdef PORT`, and `func_80081C30`'s fix into the matched C itself.
- `include/`: headers only the port's C includes.
- `build/`: generated by each build and never committed.
